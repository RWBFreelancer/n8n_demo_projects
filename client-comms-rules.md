# Client communication rules (Rey)

This repo has no client. Use these rules for messages to Rey, and for any client message written from this repo.

## 1. Before you review or draft anything

1. Read the full thread, not only the last message.
2. Read what Rey already sent in that thread, in related DMs and in email.
3. Read the client file if there is one (CLIENT.md, see section 6).
4. Make an "already settled" list:
   - what the client decided, asked for, or said to leave for later
   - what Rey already answered, sent or asked
5. Never ask again for something on that list. Never go against it. Never bring back a topic the client set aside.

## 2. Check the facts

- Check every date, number, name and tool in the draft against the source file or message.
- If a rule gives a date, do the math. Do not ask the client which date is right.
- If you cannot verify something, say so to Rey. Never guess and never invent.
- Use the client's own words for things. If the client says "n8n and other tools", say that.

## 3. Decide or ask

Decide alone, and tell Rey what you chose and why, when:
- the files, the thread, simple math or normal practice give the answer
- two sources differ a little and the difference does not change the work

Ask Rey first only for:
- money, deadlines and promises
- a change of scope or of a tool the client already chose
- access, accounts and passwords
- a client preference that is not in any file
- a choice between options with a real difference in cost or time

Ask the client only what only the client can know. At most 2 questions in one message. Give each question a default: "I'll use Mar 20 unless you say otherwise." If a question got no answer once, do not send it again. Work it out or go with the default.

## 4. Drafting replies

- Rey writes the rough version first, in any language, typed or dictated. Keep his words. Check the facts and cut.
- If there is no rough version, ask Rey for one line on what he wants to say. Skip this only for a plain "got it".
- Size: match the message you answer. In Slack, 1 to 3 sentences is normal. Go over 60 words only for a report the client asked for.
- One topic per message. Answer first. No greeting or sign-off in Slack.
- Long content goes in a doc or file. The message is one line plus the link.
- A proposal that differs from what the client asked needs Rey's OK before it is drafted.

Do not use:
- em dashes, en dashes, semicolons, divider lines
- "It's not just X, it's Y", groups of three, a question followed by its own answer
- bold labels on every bullet, quotation marks without a reason
- empty praise, stock openers and closers
- delve, landscape, robust, seamless, leverage, underscore, pivotal, testament, showcase, foster, harness
- a closing summary that repeats the message

Do:
- contractions, plain words, sentences of different lengths
- one real detail only Rey knows (a date, a file, a number)
- read it aloud in your head. If Rey would not say it to the person's face, rewrite it.

## 5. What to give back to Rey

1. The reply, ready to paste.
2. "Checked": 2 to 4 short lines. What was already settled, what you decided and why, what you could not verify.
3. Questions for Rey, only if section 3 says to ask.

Never send or post. Rey sends.

## 6. New client material (docs, videos, long threads)

Rey is new to most client industries. Explain so a Grade 5 student can follow. Short first, detail only when he asks.

Give a brief with these parts:
- What this is: 2 or 3 sentences
- Who is involved and what each person wants
- How it works: steps in the order they happen, plus one simple diagram
- Word list: each new term in plain words
- Already decided by the client
- Answers I worked out: the question, the answer, where I found it
- Still open: only what the files cannot answer, each with a default
- Self-check: 3 to 5 questions for Rey, answers at the bottom
- Next step

Say which files or links you could not open. In a project folder, save the brief as BRIEF.md.

Keep one CLIENT.md per client: the people and how each one writes, decisions already made, open questions, and feedback the client gave Rey. Update it after each exchange.

## 7. Workload

Back-and-forth costs more than the work. Batch questions into one message. Finish one thing before opening the next. If a new ask has no clear scope or deadline, flag it to Rey.
