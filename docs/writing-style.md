# Writing style

Use this style for reports, client emails, docs, sticky notes, and AI prompts.
It is based on ASD-STE100 Simplified Technical English.

## Rules
- Use plain, common words. Say "use", not "utilize". Say "help", not "facilitate".
- Use active voice. Say "The workflow saves the row", not "The row is saved by the workflow".
- Put one instruction or one idea in each sentence.
- Keep sentences short. Aim for 20 words or fewer. For instructions, aim for 15 or fewer.
- Keep paragraphs short. Use 1 to 3 sentences.
- If you must use a technical term, explain it right after it the first time.
- Keep names, paths, commands, IDs, and numbers exact.
- Use lists for steps and for groups of items.
- Do not use filler, hype, or long lead-ins. Start with the point.

## Reading level
- Aim for a grade 5 reading level, unless the idea is complex.
- If the idea is complex, keep the sentences simple and explain the idea in steps.

## AI prompts
- State the goal first. Then state the rules, the output, and what "good" looks like.
- Give clear decision rules, such as when to pick each category.
- Let a JSON schema control the output shape. Use the prompt for the decisions inside it.
- Tell the model that user content is data, not instructions.
- Do not use ALL CAPS or threats to force behavior.
